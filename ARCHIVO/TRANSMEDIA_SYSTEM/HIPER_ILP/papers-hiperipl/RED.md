# RED — Constitución política y gramática del disenso

*Vía roja disciplinada. Cómo HiperIPL se gobierna, cómo resiste captura, y cómo los operadores de fork formalizan el disenso — sin prometer utopía.*

---

## §0 — Posición en la future-machine

RED atraviesa **Capa 4 (Grafista)** como **política del grafo** y los **transversales Pipeline/Cristalizador** como gobernanza del refresh.

- **Grafista:** quién puede añadir nodos, con qué peso, qué forks son legítimos.
- **Pipeline:** orquestación del ciclo deliberativo (cuándo se cierra una ronda, cuándo `persistir`).
- **Cristalizador:** propone infraestructura — pero no la impone (riesgo zigurat).

El nodo azul muestra el resultado; RED define **quién tiene voz** y **quién no puede ocupar el centro**.

## §3 — HiperIPL desde la lente RED

### 3.1 Eje voz / mando en el dispositivo

| Posición mando | Fantasma en HiperIPL | Respuesta candidata (no decidida) |
|---|---|---|
| Zigurat (Core dev) | Equipo no admite fork | Core open source + exit-to-community |
| Templo (stakers) | Visibilidad comprada | Transparencia stake + FQ |
| Parlamento (archivo) | Firmas van a trámite | Persistencia inmutable |
| Plaza (cuerpo) | Solo quien tiene wallet/hardware | Acceso gratuito + prueba persona |

### 3.2 Los tres tribunales

| Tribunal | Pregunta | Exigencia sobre diseño |
|---|---|---|
| **Marx** | ¿Quién posee validadores/capital? | SPEC?-004: 1p1v, FQ, acceso libre |
| **Freud** | ¿Se elimina fricción humana? | Fases de discusión, no solo firma |
| **Marcuse** | ¿Firmar sustituye actuar? | Derivación a acción + medición efecto |

### 3.3 Operadores de fork como política

| Op | Gestos ciudadanos | Límite (anti-NRx) |
|---|---|---|
| `⊢` | Adoptar enmienda, distro consensuada | Requiere trazabilidad pública |
| `⊬` | Rechazar linaje: "esta distro no es HiperIPL" | Documentar motivo + cita |
| `⊘` | Heredar reglas IPL estatales sin autora | Marcar procedencia |
| `⥱` | Reclamar paternidad ilustrada / robespierreana | Sospecha de captura ideológica |
| `⟲` | Dos distros, mismo linaje, combate | Voice interna antes de exit |
| `≈` | Iniciativas paralelas | No fusionar sin deliberación |

Marx 1882: modelo de **`⊬`** — el padre rechaza al hijo que habla en su nombre.

The DAO 2016: modelo de **gracia** — excepción comunitaria a la regla.

### 3.4 Exit-to-community vs network state

| | Network state (Balaji/NRx) | HiperIPL (aspiración RED) |
|---|---|---|
| Salida | Primera opción | Último recurso |
| Gobernanza | Fundador vitalicio → ? | Roadmap a comunidad (SPEC?-019) |
| Humanos | Contingentes / élite | Titulares de voz |
| Fork | Secesión limpia | Gracia + continuidad |

### 3.5 Schmitt: el soberano del fork

Si solo un multisig puede bifurcar el Core, **Schmitt vuelve**. Opciones documentadas:

- Fork permissionless (cualquier distro).
- Fork con supermajoría on-chain.
- Fork con tribunal off-chain (jurado) — peligro templo.
- **Ninguna elegida** — SPEC?-012.
